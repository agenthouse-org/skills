## Core idea

The Alpha Pyramid is an attention model for organizational work. A typical organization devotes most resources and attention to RUN, less to BUILD, and very little to ALPHA. The model makes that distribution visible and helps leaders decide whether it still serves the organization.

The goal is not a universal target ratio. The useful question is whether the present allocation supports the organization's context, ambition, and risk.

## The three levels

### RUN

RUN comprises recurring work required to keep the organization functioning. Examples include administration, accounting, reporting, order processing, data maintenance, infrastructure operations, routine support, and recurring marketing activities.

RUN is essential. Improve it to reduce avoidable attention, friction, handoffs, and escalation. Consider elimination, simplification, standardization, automation, or selective outsourcing. Outsource execution only when appropriate; retain accountable decisions.

### BUILD

BUILD creates or implements something new. Examples include product development, software development, customer projects, campaigns, new processes, new organizational structures, recruiting new roles, workshops, experiments, and change projects.

BUILD needs more judgment, creativity, and contextual knowledge than routine RUN. It is the bridge through which an ALPHA idea becomes operational reality.

### ALPHA

ALPHA is deliberate unconventional thinking: questioning what appears self-evident, reframing the business, imagining options people hesitate to say aloud, defining a new vision, and exploring potentially disruptive paths.

ALPHA is not random eccentricity. It combines openness, constructive challenge, curiosity, and the discipline to test ideas. It can strengthen identity and strategy, but it provides no guarantee of revenue, employee satisfaction, or investor approval.

## Boundaries and flow

Classify work by its current purpose:

- Asking whether a product should be free may be ALPHA.
- Testing that proposition with customers is BUILD.
- Operating the proven offer repeatedly becomes RUN.

An activity can contain mixed elements. Decompose it when the distinction matters.

Healthy innovation capacity requires flow:

```text
ALPHA: challenge and frame
   -> BUILD: test and implement
      -> RUN: operate reliably
         -> insight and released capacity feed ALPHA again
```

A backlog of ideas without implementation indicates an ALPHA-to-BUILD constraint. Many projects without meaningful change indicate a BUILD effectiveness problem. Constant escalation indicates an unstable or overloaded RUN.

## Rebalancing the pyramid

The book asks what would happen if ALPHA received substantially more attention and RUN required less. Rebalancing can mean:

- doing less unnecessary RUN;
- performing necessary RUN more efficiently;
- protecting attention for ALPHA;
- reserving capacity to translate ALPHA into BUILD;
- accepting bounded failure as part of exploration.

Do not invert the pyramid mechanically. Stable, regulated, or safety-critical operations may require substantial RUN. Rebalance deliberately rather than chasing a fashionable ratio.

## Continuous improvement

Apply a meta-level of improvement across all three levels. RUN, BUILD, and even ALPHA benefit from clear roles, workable rules, reflection, and iteration. “Efficiently unconventional” is more useful than uncontrolled ideation.

Optimize in a practical sequence when appropriate:

1. Stabilize and simplify RUN.
2. Improve BUILD so ideas can be tested and implemented.
3. Establish repeatable conditions for ALPHA.
4. Repeat cyclically.

## Interpretation cautions

- Do not demean operational work.
- Do not equate ALPHA with every creative meeting.
- Do not classify all projects as innovation.
- Do not assume more ALPHA is always better.
- Do not use the framework as a substitute for validation or specialist methods.
